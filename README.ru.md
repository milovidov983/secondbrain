# secondbrain

**Second brain, который ведёт себя сам.** Obsidian vault на любую тему. Писать страницы, связывать их и поддерживать порядок берёт на себя Claude Code. Вы курируете, бухгалтерия на Claude.

[English version](README.md)

В основе паттерн *LLM Wiki* Андрея Карпати. Обычный RAG перечитывает документы при каждом вопросе. Здесь LLM один раз «компилирует» их в постоянную wiki из связанных страниц. Перекрёстные ссылки уже стоят, противоречия уже помечены, и каждый новый источник или вопрос делает wiki богаче.

```
 вы                           Claude Code                          Obsidian vault
 ──                           ───────────                          ──────────────
 источник     ──ingest──▶     читает, пишет сводку,          ──▶   .raw/   (оригиналы, не меняются)
 вопрос       ──query───▶     обновляет 5–15 связанных       ──▶   wiki/   (страницы + индекс,
 «сохрани»    ──/save───▶     страниц, помечает противоречия,              лог, hot cache)
 заметка в Inbox/ ──разбор──▶ ведёт индекс, лог, кэш         ──▶   CLAUDE.md (схема vault)
```

Подходит для любой темы: хобби, исследование, изучение языка, работа, вся жизнь, кодовая база.

## Быстрый старт

Нужны [Claude Code](https://claude.com/claude-code), git и bash. [Obsidian](https://obsidian.md) нужен, чтобы смотреть vault (не обязательно, но рекомендуется).

```bash
git clone https://github.com/milovidov983/secondbrain.git
cd secondbrain
./install.sh --vault ~/vault          # спросит: пресеты, inbox, имя, назначение, язык
```

Дальше:

```bash
cd ~/vault && claude
> /wiki                                # Claude доводит настройку: области, источники, ваши конвенции
> ingest https://example.com/some-article
```

В Obsidian: Open folder as vault → `~/vault`, затем включите CSS-сниппет `vault-colors` (Settings → Appearance → CSS snippets).

Хотите, чтобы всё сделал Claude? Запустите `./install.sh` без `--vault`, откройте `claude` в любой папке и скажите «настрой мне second brain».

Язык страниц выбирается при установке (`--lang Russian`). Скиллы понимают команды и по-русски: «разбери inbox», «продолжим», «что мы знаем про X».

## Что делает `install.sh`

1. **Скиллы.** Копирует скиллы из `skills/` в `~/.claude/skills/`. Если установленный скилл был изменён, его старая версия сначала уходит в `~/.claude/skills-backup/<время>/`.
2. **Глобальные инструкции.** Добавляет в `~/.claude/CLAUDE.md` короткую секцию между маркерами `secondbrain:begin` / `secondbrain:end`. Так Claude знает о vault из любого проекта. Повторный запуск с `--vault` обновляет путь, а резервная копия файла сохраняется рядом.
3. **Vault (с `--vault`).** Создаёт только недостающее и ничего не перезаписывает: папки, шаблоны, `CLAUDE.md`, стартовые `index` / `log` / `hot` / `overview`, настройки Obsidian, `.gitignore`, `git init`.

Скрипт можно запускать повторно. `--dry-run` покажет, что будет сделано. Пример без вопросов:

```bash
./install.sh --vault ~/vault --preset research,personal --modules inbox \
  --name "Сон" --purpose "Исследую науку о сне и свои привычки" --lang Russian --yes
```

## Пресеты: о чём vault

Ядро (источники, сущности, концепции, вопросы, сравнения) подходит для любой темы. Пресет добавляет типы страниц, папки и шаблоны под конкретный вид vault. Пресеты можно сочетать через запятую.

| Пресет | Для чего | Добавляет |
|---|---|---|
| `general` | тема, которую изучаете: кулинария, история, инвестиции | ничего, только ядро |
| `personal` | жизнь: цели, здоровье, финансы, люди | `goals/`, `areas/`, `reviews/` |
| `research` | статьи, утверждения, развивающийся тезис | `papers/`, `theses/` |
| `learning` | предмет или навык: книги, курсы, упражнения | `resources/`, `practice/` |
| `project` | работа, команда, бизнес | `decisions/`, `meetings/` |
| `codebase` | разобраться в кодовой базе или системе | `modules/`, `flows/`, `decisions/` |

Список выводит `./install.sh --list`, подробности в [skills/wiki/references/presets.md](skills/wiki/references/presets.md). Пресет можно добавить позже, достаточно сказать Claude «добавь пресет research». Свои типы страниц (рецепты, клиенты, растения…) описываются в разделе `## My Conventions` файла `CLAUDE.md` vault, примеры лежат в [examples/](examples/).

**Модули** добавляют необязательные процессы:

| Модуль | Что даёт |
|---|---|
| `inbox` | `Inbox/` для заметок в свободной форме, `Tasks/` и еженедельный разбор («разбери inbox») |

## Каждый день

| Хочу | Сказать |
|---|---|
| Добавить статью, PDF, заметки со встречи, картинку | `ingest <путь или URL>` (файл можно сначала положить в `.raw/`) |
| Спросить vault | `query: …`, «что мы знаем про X», `query deep: …` |
| Сохранить хороший ответ или обсуждение | `/save` |
| Продолжить с того места, где остановились | «продолжим» |
| Быстро что-то записать (модуль inbox) | писать в `Inbox/YYYY-MM-DD.md` в любом виде |
| Разобрать inbox (раз в неделю) | «разбери inbox» |
| Проверить здоровье vault (раз в несколько недель) | «lint the wiki» |
| Подтвердить, что страница верна | «проверил [[Страница]]» |
| Узнать, что стоит проверить | «что проверить?» |
| Контекст vault в другом проекте | ничего: Claude прочитает `wiki/hot.md`, потом `wiki/index.md` |

Зачем всё устроено именно так и в каком ритме с этим работать, описано в [METHODOLOGY.md](METHODOLOGY.md) (на английском).

## Главные правила

- **`.raw/` не редактируется.** По этим оригиналам проверяются wiki-страницы.
- **Frontmatter на каждой странице wiki**, связи через `[[wikilinks]]`, имена файлов уникальны.
- **`wiki/index.md`** обновляется при каждом создании или удалении страницы. **`wiki/log.md`** только пополняется, новые записи сверху. **`wiki/hot.md`** (~500 слов) перезаписывается после каждой операции.
- **Противоречия помечаются, а не затираются:** `> [!contradiction]` на обеих страницах.
- **Доверие и свежесть видны во frontmatter.** У каждой страницы есть `description` в одну строку. Поле `reviewed` ставите только вы, когда проверили страницу; если Claude потом её поменяет, видно, что проверка устарела. Страницам с фактами, которые устаревают сами (цены, версии, планы), Claude ставит `stale_after` и предупреждает, когда опирается на просроченную.
- **`CLAUDE.md` vault главнее скиллов.** Хотите, чтобы Claude работал в вашем vault иначе, поменяйте его.

## Бэкап и синхронизация

Vault — обычная папка с markdown-файлами в git.

1. Создайте **приватный** репозиторий (GitHub, GitLab, любой git-хостинг) и запушьте: `git remote add origin <url> && git push -u origin main`.
2. Поставьте в Obsidian community-плагин **obsidian-git**: он сам делает коммиты и push.
3. Obsidian и Claude Code коммитят в один репозиторий, поэтому перед `git push` всегда делайте `git pull --rebase`.

На новой машине: установите Claude Code и Obsidian, склонируйте этот пакет и свой vault, затем запустите `./install.sh --vault <путь к vault>`. Скрипт добавит только недостающее, ваш `CLAUDE.md` и страницы останутся как есть. Весь рабочий контекст (hot cache, индекс, лог) хранится в самом vault, поэтому локальная история Claude Code для продолжения не нужна.

## Обновление

Источник правды для скиллов — этот репозиторий. Сделайте здесь `git pull`, затем `./install.sh`. Если вы правили скилл прямо в `~/.claude/skills/`, старая копия уйдёт в `~/.claude/skills-backup/`. Чтобы сохранить свои правки, сделайте форк и меняйте скиллы в нём.

## Если что-то не так

- **Claude не ходит в vault из других проектов.** Проверьте секцию `secondbrain` в `~/.claude/CLAUDE.md` и строку `Vault path:`. Исправляет `./install.sh --vault <путь>`.
- **Скилл не срабатывает.** Проверьте, что есть `~/.claude/skills/<скилл>/SKILL.md`, и перезапустите Claude Code.
- **`git push` отклонён (fetch first).** obsidian-git успел закоммитить: `git pull --rebase`, потом push.
- **Новая сессия не помнит контекст.** В прошлый раз не обновили `wiki/hot.md`. Скажите «продолжим», и Claude восстановит контекст по логу.
- **Callouts и цвета папок выглядят обычно.** Включите сниппет `vault-colors` в Obsidian (Appearance → CSS snippets).
