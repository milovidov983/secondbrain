# secondbrain

**Second brain, который ведёт себя сам.** Obsidian vault на любую тему. Писать страницы, связывать их и поддерживать порядок берёт на себя ваш агент — [Claude Code](https://claude.com/claude-code), [OpenCode](https://opencode.ai) или любой агент, который читает `AGENTS.md` и скиллы в формате `SKILL.md`. Вы курируете, бухгалтерия на агенте.

[English version](README.md)

В основе паттерн *LLM Wiki* Андрея Карпати. Обычный RAG перечитывает документы при каждом вопросе. Здесь LLM один раз «компилирует» их в постоянную wiki из связанных страниц. Перекрёстные ссылки уже стоят, противоречия уже помечены, и каждый новый источник или вопрос делает wiki богаче.

```
 вы                           ваш агент                            Obsidian vault
 ──                           ─────────                            ──────────────
 источник     ──ingest──▶     читает, пишет сводку,          ──▶   .raw/   (оригиналы, не меняются)
 вопрос       ──query───▶     обновляет 5–15 связанных       ──▶   wiki/   (страницы + индекс,
 «сохрани»    ──/save───▶     страниц, помечает противоречия,              лог, hot cache)
 заметка в Inbox/ ──разбор──▶ ведёт индекс, лог, кэш         ──▶   AGENTS.md (схема vault)
```

Подходит для любой темы: хобби, исследование, изучение языка, работа, вся жизнь, кодовая база.

## Быстрый старт

Нужны [Claude Code](https://claude.com/claude-code) или [OpenCode](https://opencode.ai), git и bash. [Obsidian](https://obsidian.md) нужен, чтобы смотреть vault (не обязательно, но рекомендуется).

**Windows нативно не поддерживается**: установщик написан на bash, а vault использует симлинк (`CLAUDE.md` → `AGENTS.md`). На Windows используйте [WSL](https://learn.microsoft.com/windows/wsl/) и запускайте всё внутри него.

```bash
git clone https://github.com/milovidov983/secondbrain.git
cd secondbrain
./install.sh --vault ~/vault          # спросит: пресеты, inbox, имя, назначение, язык
```

По умолчанию установка идёт **для обоих** агентов — Claude Code и OpenCode. Только для одного: `./install.sh --agent opencode` (или `--agent claude`).

Дальше:

```bash
cd ~/vault && claude                  # или: opencode
> /wiki                                # агент доводит настройку: области, источники, ваши конвенции
> ingest https://example.com/some-article
```

В Obsidian: Open folder as vault → `~/vault`, затем включите CSS-сниппет `vault-colors` (Settings → Appearance → CSS snippets).

Хотите, чтобы всё сделал агент? Запустите `./install.sh` без `--vault`, откройте `claude` или `opencode` в любой папке и скажите «настрой мне second brain».

Язык страниц выбирается при установке (`--lang Russian`). Скиллы понимают команды и по-русски: «разбери inbox», «продолжим», «что мы знаем про X».

## Что делает `install.sh`

1. **Скиллы.** Копирует скиллы из `skills/` в родные папки агентов: `~/.claude/skills/` (Claude Code) и `~/.config/opencode/skills/` (OpenCode). Если установленный скилл был изменён, его старая версия сначала уходит в `<конфиг-папка>/skills-backup/<время>/`.
2. **Глобальные инструкции.** Добавляет короткую секцию между маркерами `secondbrain:begin` / `secondbrain:end` в `~/.claude/CLAUDE.md` и `~/.config/opencode/AGENTS.md`. Так агент знает о vault из любого проекта. Повторный запуск с `--vault` обновляет путь, а резервная копия файла сохраняется рядом.
3. **Команды (OpenCode).** Пишет обёртки `/wiki`, `/save` и `/inbox` в `~/.config/opencode/commands/`, чтобы слэш-команды работали как в Claude Code.
4. **Vault (с `--vault`).** Создаёт только недостающее и ничего не перезаписывает: папки, шаблоны, `AGENTS.md` (плюс симлинк `CLAUDE.md` для Claude Code), стартовые `index` / `log` / `hot` / `overview`, настройки Obsidian, `.gitignore`, `git init`. Vault от старой версии пакета мигрирует: его `CLAUDE.md` переименовывается в `AGENTS.md` с сохранением содержимого.

Скрипт можно запускать повторно. `--dry-run` покажет, что будет сделано. Пример без вопросов:

```bash
./install.sh --vault ~/vault --preset research,personal --modules inbox \
  --name "Сон" --purpose "Исследую науку о сне и свои привычки" --lang Russian --yes
```

## Пресеты: о чём vault

Ядро (источники, сущности, концепции, вопросы, сравнения) подходит для любой темы. Пресет добавляет типы страниц, папки и шаблоны под конкретный вид vault. Пресеты можно сочетать через запятую.

| Пресет | Для чего | Добавляет |
|---|---|---|
| `general` | тема, которую изучаете: кулинария, история, инвестиции | ничего, только ядро |
| `personal` | жизнь: цели, здоровье, финансы, люди | `goals/`, `areas/`, `reviews/` |
| `research` | статьи, утверждения, развивающийся тезис | `papers/`, `theses/` |
| `learning` | предмет или навык: книги, курсы, упражнения | `resources/`, `practice/` |
| `project` | работа, команда, бизнес | `decisions/`, `meetings/` |
| `codebase` | разобраться в кодовой базе или системе | `modules/`, `flows/`, `decisions/` |

Список выводит `./install.sh --list`, подробности в [skills/wiki/references/presets.md](skills/wiki/references/presets.md). Пресет можно добавить позже, достаточно сказать агенту «добавь пресет research». Свои типы страниц (рецепты, клиенты, растения…) описываются в разделе `## My Conventions` файла `AGENTS.md` vault, примеры лежат в [examples/](examples/).

**Модули** добавляют необязательные процессы:

| Модуль | Что даёт |
|---|---|
| `inbox` | `Inbox/` для заметок в свободной форме, `Tasks/` и еженедельный разбор («разбери inbox») |

## Каждый день

| Хочу | Сказать |
|---|---|
| Добавить статью, PDF, заметки со встречи, картинку | `ingest <путь или URL>` (файл можно сначала положить в `.raw/`) |
| Спросить vault | `query: …`, «что мы знаем про X», `query deep: …` |
| Сохранить хороший ответ или обсуждение | `/save` |
| Продолжить с того места, где остановились | «продолжим» |
| Быстро что-то записать (модуль inbox) | писать в `Inbox/YYYY-MM-DD.md` в любом виде |
| Разобрать inbox (раз в неделю) | «разбери inbox» |
| Проверить здоровье vault (раз в несколько недель) | «lint the wiki» |
| Подтвердить, что страница верна | «проверил [[Страница]]» |
| Узнать, что стоит проверить | «что проверить?» |
| Контекст vault в другом проекте | ничего: агент прочитает `wiki/hot.md`, потом `wiki/index.md` |

Зачем всё устроено именно так и в каком ритме с этим работать, описано в [METHODOLOGY.md](METHODOLOGY.md) (на английском).

## Главные правила

- **`.raw/` не редактируется.** По этим оригиналам проверяются wiki-страницы.
- **Frontmatter на каждой странице wiki**, связи через `[[wikilinks]]`, имена файлов уникальны.
- **`wiki/index.md`** обновляется при каждом создании или удалении страницы. **`wiki/log.md`** только пополняется, новые записи сверху. **`wiki/hot.md`** (~500 слов) перезаписывается после каждой операции.
- **Противоречия помечаются, а не затираются:** `> [!contradiction]` на обеих страницах.
- **Доверие и свежесть видны во frontmatter.** У каждой страницы есть `description` в одну строку. Поле `reviewed` ставите только вы, когда проверили страницу; если агент потом её поменяет, видно, что проверка устарела. Страницам с фактами, которые устаревают сами (цены, версии, планы), агент ставит `stale_after` и предупреждает, когда опирается на просроченную.
- **`AGENTS.md` vault главнее скиллов.** Хотите, чтобы агент работал в вашем vault иначе, поменяйте его.

## Бэкап и синхронизация

Vault — обычная папка с markdown-файлами в git.

1. Создайте **приватный** репозиторий (GitHub, GitLab, любой git-хостинг) и запушьте: `git remote add origin <url> && git push -u origin main`.
2. Поставьте в Obsidian community-плагин **obsidian-git**: он сам делает коммиты и push.
3. Obsidian и ваш агент коммитят в один репозиторий, поэтому перед `git push` всегда делайте `git pull --rebase`.

На новой машине: установите агента и Obsidian, склонируйте этот пакет и свой vault, затем запустите `./install.sh --vault <путь к vault>`. Скрипт добавит только недостающее, ваш `AGENTS.md` и страницы останутся как есть. Весь рабочий контекст (hot cache, индекс, лог) хранится в самом vault, поэтому локальная история агента для продолжения не нужна.

## Обновление

Источник правды для скиллов — этот репозиторий. Сделайте здесь `git pull`, затем `./install.sh`. Если вы правили скилл прямо в установленной папке скиллов, старая копия уйдёт в `<конфиг-папка>/skills-backup/`. Чтобы сохранить свои правки, сделайте форк и меняйте скиллы в нём.

Обновление не трогает `AGENTS.md` и страницы уже существующего vault. Если в обновлении появились новые соглашения (например, поля `description`, `reviewed` и `stale_after`), сравните `AGENTS.md` вашего vault с `skills/wiki/assets/vault-AGENTS.md.template` и перенесите новые строки, затем скажите «lint the wiki»: он покажет страницы без новых полей и может их заполнить.

## Если что-то не так

- **Агент не ходит в vault из других проектов.** Проверьте секцию `secondbrain` и строку `Vault path:` в `~/.claude/CLAUDE.md` (Claude Code) или `~/.config/opencode/AGENTS.md` (OpenCode). Исправляет `./install.sh --vault <путь>`.
- **Скилл не срабатывает.** Проверьте, что есть `<конфиг-папка>/skills/<скилл>/SKILL.md` (`~/.claude/skills/` или `~/.config/opencode/skills/`). Перезапустите Claude Code; OpenCode подхватывает скиллы автоматически.
- **`/wiki` или `/save` не работают в OpenCode.** Проверьте `~/.config/opencode/commands/`; перезапустите `./install.sh --agent opencode`.
- **`git push` отклонён (fetch first).** obsidian-git успел закоммитить: `git pull --rebase`, потом push.
- **Новая сессия не помнит контекст.** В прошлый раз не обновили `wiki/hot.md`. Скажите «продолжим», и агент восстановит контекст по логу.
- **Callouts и цвета папок выглядят обычно.** Включите сниппет `vault-colors` в Obsidian (Appearance → CSS snippets).
